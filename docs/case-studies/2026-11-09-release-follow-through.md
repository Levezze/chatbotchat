## Existing-plan implications

| Existing stage | Qualification or data distinction |
| --- | --- |
| #113 messaging trial | Measure transport commit/dispatch/result/receipt separately from a ready request's disposition and actual work. A failed tool result cannot become a successful-send claim. |
| #114 decisions | Distinguish observed native pending/refusal from agent interpretation, product decision, resource conflict and ordinary coordinator action. Keep origin/evidence and uncertainty explicit. |
| #115 work and attention | Preserve an owner action after reading its message. Age it from its ready/request time, not a poll, unrelated activity or a status report. Only action-specific disposition/outcome, explicit supersession or cancellation changes that obligation. |
| #116 views | Show transport health and meaningful work separately. Preserve current revision and distinguish coding, code complete, validation pending, ready to merge, merged, deploying and serving. |

Disposition is an actionable answer, start, scoped refusal with evidence, or one
concrete missing fact. Acknowledgement or transport receipt is not disposition.
Record owner, affected action, source request, meaningful timestamps and evidence
through existing work/request records. These need updates at meaningful changes,
not an AI-written log on every tool call. Unrelated blocked actions stay separate.

The proposed ten-minute recovery sweep handles delivery only. The already-agreed
core responsibility scheduler retains due coordinator obligations, including when
all messages have been read. It can seek attention through the supported adapter
for the existing authorized workflow; it does not acquire new execution authority
or silently broaden a native chat-check automation. Exited-engine/Stop limitations
and actual holds remain visible.

An isolated trial must include a busy coordinator receiving a ready request,
continuing a different conversation, then disposing of that request within the
trial's declared criteria. Later #115 tests preserve that obligation across read,
unrelated activity, report completion, restart and compaction. Absence of a new
message must not erase unfinished ownership. No extra orchestration tier or new
issue decomposition is proposed by this record.

## Immediate source correction and later host qualification

The existing role-skill source now directs a Primarch to disposition ready
requests before yielding, preserve unfinished ownership after a report and
avoid silently adding discretionary verification gates. Chapter Masters credit
applicable exact-revision evidence while revalidating relevant changes or
invalidated proof. Native refusals need actual result evidence; other holds and
uncertainty stay separately labelled. These source edits are not installed
instructions or a claimed behavioral fix in running agents.

Stage #115 can qualify a bounded voluntary-turn-end guard on hosts supporting it.
Claude's [Stop hook](https://code.claude.com/docs/en/hooks#stop) documents continuation
after a normal response and excludes user interrupts. A CBC guard must honor real
Stop/holds, check runnable authorized obligations and permit at most one reminder
per qualifying obligation revision with a cooldown. Native loop limits alone are
insufficient because tool calls can reset them. Missing support on another profile
remains explicit. No hook is installed or treated as a universal wake API here.

Provider observers own PR/check/deployment facts, not the meaning of "actively
coding" or unpublished source completion. Owner assertions retain their own fields
and provenance. Neither a fresh prose summary nor absent GitHub activity may
overwrite observed merge/deployment state or invent implementation progress.
