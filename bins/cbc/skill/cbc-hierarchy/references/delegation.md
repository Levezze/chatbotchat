# Create only the owner that is needed

A Primarch delegates implementation to an independent Chapter Master chat.
A Chapter Master creates native implementation subagents directly. Subagents are local tools,
not another persistent CBC tier. Do not substitute a Primarch-owned implementation subagent
for the required Chapter Master.

Create a fresh Chapter Master session for each unrelated assignment. One finite umbrella
feature may include related parallel tasks; sharing a domain, repository or available session
does not make separate work part of that feature. Keep the original session for its phases,
fixes and later investigation. Record the assignment-to-session/member/room/PR links on the
Primarch board and retain them after completion. Retire completed owners instead of giving
them unrelated work. More independent sessions are preferable to mixed implementation history.

Use the assigned host. Primarchs run in Codex; Chapter Masters and their native subagents
run in Codex or Claude as the user assigns. Use supported native create/attach
tools and obey their actual caller restrictions. No private app stores or terminal-wrapper loops.
A native child handle is not an independent sidebar chat. Record actual returned IDs; reconcile
an uncertain create before duplicating it. If host creation is unavailable, provide one complete
attach instruction. Continue other work rather than repeatedly probing creation.

A lead assignment needs only: goal, repository/workspace, scope and acceptance criteria,
context/member, Primarch/report route, source links and relevant existing authority/holds.
State the smallest deliverable, non-goals and done evidence within that assignment.
Include verification scope: additional test machinery after gates pass is still added work.
Put worthwhile unrelated follow-ups aside; raise a material scope expansion once rather
than quietly turning it into the current implementation.
Within the user's delegation, ordinary task splitting and subagent creation need no fresh approval.
Do not invent separate lifecycle roles, registration rooms or individual permission grants for
each native helper. Keep a handle and bounded write scope so live writers do not collide.
Subagents return results to their spawning parent by default. A direct cross-chat handoff
needs the exact existing recipient and actual user-source/communication-grant references in
the spawn assignment. Verify once at intake; refresh only after binding, authority or context
loss. This prospective assignment rule does not authorize replay of a previously refused send.

Bind each writer to the correct native workspace/worktree before editing where the host requires
it. A shell cd cannot replace a required native binding. Preserve actual custody and native
refusals; creating another actor is not a remedy for a stopped operation.
Use the existing configured permission mode; do not silently change it.

New session titles use session_title.py. A rename problem is cosmetic, not a delivery gate.
Use cbc-handoff only to replace an actual session, never as the normal task delegation protocol.
