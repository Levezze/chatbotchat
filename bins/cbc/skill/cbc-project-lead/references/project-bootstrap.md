# Legacy project bootstrap compatibility

The Emperor is reserved for the future dashboard and is dormant before it exists.
Old /emperor --project ... --repos ... examples do not automatically create chats or routes.

If the user separately requests named Primarch chats, use supported independent-chat creation
under that explicit request. Reuse existing owners, preserve configured host placement and
do not create an Emperor reporting relationship. A pending native result is not a running chat;
reconcile uncertainty before duplicating creation.

Read `../../cbc-hierarchy/references/rooms.md` for any actually needed instruction/clarification
exchange. Future dashboard data arrives through shared server state, not Primarch reports.

A separately requested Primarch assignment supplies its repository/workspace, role, context/member,
actual mandate and source links. Human-owned questions go directly to the user today.
No Emperor setup or acknowledgement is a prerequisite for repo delivery.
